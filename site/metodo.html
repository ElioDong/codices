Technical documentation

Method

The project's technical choices are not neutral: each one answers a requirement of durability, interoperability or accessibility. This page makes them explicit.

The workflow

Each phase has an owner, a deliverable and an acceptance criterion. A phase is not considered complete until its deliverable passes the criterion.

  1. Survey

    Measurement of the copy, detection of watermarks and catchwords, photography of its state of preservation.

    Deliverable: survey record

  2. Digitisation

    Capture at 600 dpi with a colour target and a millimetre scale; uncompressed TIFF master, JPEG 2000 derivatives for the web.

    Deliverable: master archive

  3. Description

    Compilation of Dublin Core metadata, transcription in TEI P5, alignment with controlled vocabularies.

    Deliverable: descriptive record

  4. Publication

    Generation of the HTML5 pages, publication of the images via IIIF, accessibility check, going live.

    Deliverable: site and IIIF manifest

The standards adopted

Dublin Core (ISO 15836)

Fifteen descriptive elements, all optional and all repeatable. It is the minimum standard shared by digital libraries: adopting it means that an external aggregator — Europeana, for example — can harvest our records without anyone having to write bespoke code. The cost is a loss of detail: Dublin Core cannot describe a watermark.

TEI P5

The Text Encoding Initiative is the reference XML schema for the encoding of texts. Compared with HTML, which describes the rendering, TEI describes the nature of the textual elements. The distinction matters: a line break in the manuscript and a typographic line break look the same on screen but are different things, and only the second is an editorial fact.

IIIF

The International Image Interoperability Framework exposes images through predictable URLs, of the form …/full/1200,/0/default.jpg. The practical advantage is that a scholar can place side by side, in the same interface, two leaves held in different institutions, without downloading anything.

OAIS (ISO 14721)

The reference model for long-term preservation distinguishes three packages: Submission, Archival and Dissemination Information Package. The TIFF master is the archival package; the images served to the visitor are the dissemination package. Confusing them is the most common mistake in small projects.

The site's technical choices

The site is written in plain HTML5 and CSS3, with no framework and no build step. It is a deliberate choice, and it has a price.

What is gained

  • No external dependency to update or that might disappear
  • Minimal loading times: no framework JavaScript to download
  • The code remains readable in ten years
  • The site works even with JavaScript disabled

What is lost

  • The header and footer must be repeated on every page
  • To add a manuscript, the HTML is edited by hand
  • No automatic handling of search and sorting

With six copies the balance tips in favour of having no dependencies. Beyond fifty catalogue records, repeating the header becomes a concrete risk of inconsistency, and at that point a static site generator is worth it — it still produces plain HTML, but from a single source.

Progressive enhancement

The content is present in full in the HTML. The CSS makes it readable and pleasant; the JavaScript only adds conveniences: the collection filter, the memory of the chosen theme and the menu on narrow screens. Without JavaScript one loses the filter, not access to the content. 

/* Example: the fluid typographic scale.
   The type grows with the window between a minimum and a maximum,
   with no need for dedicated media queries. */
h1 {
  font-size: clamp(2.25rem, 1.6rem + 3vw, 4rem);
}

The same principle applies to the grid of catalogue records: repeat(auto-fit, minmax(17rem, 1fr)) achieves the responsive behaviour that once required three media queries.

Accessibility

The site aims for WCAG 2.1 level AA conformance. Below are the measures adopted and how they were verified.

Accessibility measures adopted
Requirement How it is met
1.3.1 Structure Semantic HTML: <header>, <nav>, <main>, <footer>, a single <h1> per page, heading hierarchy with no skipped levels.
1.4.3 Contrast Main text at a ratio of 14:1, muted text at 5.2:1 — above the 4.5:1 threshold required for normal text.
1.4.4 Resize text Sizes in rem and clamp(): text scales up to 200% without loss of content.
1.4.10 Reflow No horizontal scrollbar down to a width of 320 px. Tables become block lists.
2.1.1 Keyboard Every function is reachable from the keyboard. The dropdown menu closes with Esc and returns focus to the button.
2.4.1 Bypass Blocks A "Skip to main content" link, the first focusable element, visible only on focus.
2.4.7 Focus Visible A focus ring on every interactive element via :focus-visible.
4.1.3 Status Messages The count of filtered results is announced with role="status" and aria-live="polite".
User preferences Respect for prefers-color-scheme, prefers-reduced-motion and prefers-contrast.

Declared limitations

The manuscript images in this prototype are sample vector illustrations: the alternative texts describe content that exists but has not been verified with real users. An evaluation carried out with people with disabilities remains to be done and cannot be replaced by an automated checklist.

Preservation over time

A website has a short life: domains expire, formats change, platforms shut down. If the descriptive data lives only inside the HTML, the collection dies with the site. For this reason the project provides for three measures.

  1. The data is separated from the presentation. The records are created as JSON files, conforming to the Dublin Core schema. The HTML is one of their possible renderings on screen, not their container.
  2. The identifiers are stable and do not depend on the domain. Each copy has an identifier codices:ms-001, which remains valid even if the site changes address.
  3. The masters are deposited elsewhere. The preservation images in TIFF are deposited with the holding institution; the site serves only the lightweight derivatives.
